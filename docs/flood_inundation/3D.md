# Flood Inundation — 3D Presentation (Phase 4)

Optional **3D flood view** on the existing 2D map. Operational analysis (extent, CSI, exposure) stays 2D.

## Architecture

| Layer | Role |
|-------|------|
| 2D (default) | `BitmapLayer` depth + `GeoJsonLayer` extent |
| 3D terrain (optional) | `TerrainLayer` — Terrarium elevation + Esri hillshade |
| 3D water | `SimpleMeshLayer` — HAND DEM + depth extrusion |
| 3D playback | Auto-advance frames + camera keyframes from manifest `camera_path` |

Backend writes a decimated mesh manifest when `map_flood_inundation` or `map_flood_inundation_hydrograph` runs with `create_map=True`. The VS Code `MapEventWatcher` inlines mesh JSON into layer metadata; the webview 🌊 ribbon panel enables pitch + mesh rendering.

## Map UI

| Control | Location |
|---------|----------|
| Enable 3D view | 🌊 flood panel |
| Terrarium terrain toggle | 🌊 flood panel |
| Cinematic camera + Play/Pause | 🌊 flood panel (hydrograph) |
| Frame scrubber | 🌊 + 🕐 time panel (synced) |
| Rotate camera | Right-drag when 3D enabled |

Hydrograph extent polygons auto-hide/show per selected frame when 3D is on.

## Agent flow (unchanged 2D + optional 3D)

```
map_flood_inundation(return_period=100)
# or
map_flood_inundation_hydrograph(max_frames=12)
# In map UI: 🌊 → Enable 3D view
```

## Caveats

- Meshes are **presentation-only** (`INUNDATION_3D_CAVEAT`).
- Water mesh Z uses the HAND job DEM; Terrarium terrain is contextual. When terrain is enabled, the client applies manifest `terrain_vertical_offset_m` (EGM96-lite orthometric → ellipsoid) for CONUS 3DEP stacks.
- Cognaterra MapLibre globe + interleaved overlay (optional flagship polish)
- Flowline-following camera path from MERIT rivers (`merit_flowline`) when stack includes clipped MERIT GeoJSON; else D8 stem / AOI-axis traverse
